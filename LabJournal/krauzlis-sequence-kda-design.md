2026-10-02. The user requested a simpler model that consumes a complete image sequence and its patches in one call, then reads the response from CLS. The explicit correction is **single layer KDA**. [The concrete design](../SecondPass/SequenceKDA/README.md) fixes one global two-head KDA, direct shared RGB patch embedding, spatial and temporal positions, terminal CLS and a small binary classifier.

Each native 100 by 100 frame contributes 100 nonoverlapping 10 by 10 pixel patches. At width 128 and key/value dimensions 64 per head, native B12/B20/B28 trials contain 2,901/3,701/4,501 tokens including CLS. Proposed parameter count is analytically 158,340; global state has 8,192 FP32 values per trial. There is no separate CNN, spatial KDA stack, GRU or second sequence mixer. Appending CLS lets it read all earlier tokens under KDA's causal operator; complete-sequence input is not bidirectional attention.

Patch-rate decay initialization uses 32- and 128-frame half-lives, with initial write strength 0.01, rather than the old 0.9-per-frame gate applied at the much faster patch update rate. These trainable initialization choices support longer initial retention without guaranteeing it. The single CLS query is not contextualized by an earlier layer, so cue-conditioned reporting must be learned in the state and classifier.

The proposed later run preserves the native 26/28 degree task, all three conditions, cues, event proportions and cross-entropy; it is not the historical 90 degree variant. Everything starts fresh, with all learned parameters trainable. Proposed Adam1e-4, FP32/full temporal gradients, batch32/micro4 and no clipping match recent optimization. At most10,000updates/320,000episodes would be pinned prospectively from measured feasibility in a proposed new8h/$5 cloud envelope. Validation-only selection and fresh paired selected/terminal tests retain target/foil/catch results for each condition.
