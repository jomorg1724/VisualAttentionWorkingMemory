# FP32 backend

The implementation needs only PyTorch. `kda_backend.py` independently implements the equations in the [official KDA recurrent and chunk reference](https://github.com/fla-org/flash-linear-attention/blob/main/fla/ops/kda/naive.py). It uses chunk-local FP32 triangular solves and carries state through the complete movie without detaching. Chunk boundaries are a computation detail; they do not reset memory or truncate gradients. Neutral zero-write padding handles native lengths not divisible by 32.

For chunk-local cumulative log decay G, innovation vectors satisfy a lower-triangular system whose off-diagonal entries are `beta_i * sum_d(k_i,d * k_j,d * exp(G_i,d-G_j,d))`. Solving with value and decayed-key right-hand sides yields `delta = U - W @ incoming_state`. The outgoing state is the decayed incoming state plus the sum of appropriately decayed key/innovation outer products. A final-only read computes exactly the appended CLS query against the final state. Earlier token queries cannot affect later state in a single KDA layer, so their unused reads are omitted in production.

The backend masks noncausal decay differences before exponentiation. It never forms unconstrained inverse-decay factors, and thus avoids overflow when learned decay becomes strong. Parameters, inputs, gates, triangular systems, innovations, state, reads and gradients remain FP32. CUDA matrix TF32 must be disabled by the worker; the backend rejects enabled TF32. Autocast and non-FP32 inputs are rejected. There is no FLA dependency: the [official chunk API](https://github.com/fla-org/flash-linear-attention/blob/main/fla/ops/kda/chunk.py) documents BF16 intermediate states, which does not satisfy this run's strict FP32 recipe.

CPU verification compares output, final state and all six input gradients, including incoming-state gradients, against the direct recurrence. It includes short chunks with nonzero incoming state, strong decay, and all 4,501 native B28 tokens at the actual two-head 64-by-64 state width. Architectural checks verify exact patch reconstruction/order, fixed time positions, one KDA layer, fresh trainable parameter count 158,340, early-frame gradient, all parameter updates, trial-state reset and order sensitivity. Run `python -m SecondPass.SequenceKDA.test_model --receipt SecondPass/SequenceKDA/verification/model_cpu.json`.

No accelerator performance claim follows from CPU parity. Cloud profiling must measure native forward/backward and renderer costs and pin the feasible training exposure before production. The default production backend is `chunk` with chunk size 32; `reference` exists for correctness comparisons only.
