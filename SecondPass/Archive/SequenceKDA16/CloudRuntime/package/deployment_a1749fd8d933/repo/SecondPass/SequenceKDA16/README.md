# One KDA layer with sixteen heads

The user requested a fresh sixteen-head KDA experiment, queued after the active three-layer cloud run. This model keeps exactly one KDA layer and reads the appended CLS token. It is a separate experiment; it inherits no trained weights, optimizer state, data stream progress or profile state.

The native RGB movie remains `[B,T,3,100,100]`. Shared Linear300→128/GELU/LayerNorm embeds each nonoverlapping 10-by-10 patch. Learned row/column positions and fixed frame-index sine/cosine features preserve the original chronological, then row/column token order. A learned CLS token is appended last. Token and classifier widths remain 128 and 128→256→2.

Within the single pre-LayerNorm residual KDA block, q/k/v/decay projections expand 128 input channels to **1,024 internal channels: sixteen heads, each with 64-dimensional keys and values**. Write strength is projected to sixteen scalars. Concatenated head reads project 1,024→128 before the residual and final CLS classifier. There are no additional KDA passes, feedforward blocks, CNNs or GRUs.

This increases memory capacity rather than dividing a fixed 128-channel internal width into smaller heads. Each trial has **65,536 FP32 state values, eight times the original two-head model**. The constructed model has **737,170 parameters in 27 trainable tensors**. Eight heads initialize decay-only half-life to 32 frames and eight to 128 frames, accounting for 100 patch updates per frame; all initial write strengths are 0.01. Gates remain trainable. With one causal layer, CLS query still originates from CLS content and end-time position; extra heads increase capacity without making that query context-dependent.

Training preserves native Krauzlis B12/B20/B28, all 29/37/45 frames, 26/28-degree changes and 57 target / 29 foil / 14 catch draws per 100. One fresh model and Adam 1e-4, FP32/full BPTT, no clipping, effective batch 32 and microbatch 4. The prospective target is 4,216 updates / 134,912 episodes, reduced before production only if native profiling requires it. Three warmup updates precede six steady profile updates; all profile state is discarded. Two validation looks use 100 trials per condition; mean AUC, then BA, then earlier checkpoint selects the model. Selected and terminal models use identical fresh final movies, 200 per condition, with all event subgroups visible.
