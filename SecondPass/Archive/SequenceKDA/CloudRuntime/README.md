# Sequence KDA cloud runtime

This attempt is isolated under `CloudRuntime`. Parent alone runs provider and SSH operations. The imported existing provider transport is read-only at import; this directory contains no API key or SSH private key.

The single A40 quote must be at most $0.49 per hour. Creation starts a new 28,800-second total cap; model work ends 600 seconds earlier. The explicit $1 storage reserve includes 24 hours of stopped-disk contingency and puts the maximum compute-plus-reserve at $4.92. No running or unknown-lifecycle pod may coexist at creation. An exclusive attempt claim forbids ambiguous create retries.

`bundle.py --output SecondPass/SequenceKDA/CloudRuntime/package` creates the scientific source receipt. `freeze_runtime.py` binds its actual SHA256 in the runtime manifest, then makes allowlisted runtime files read-only. `deploy.py check` rechecks archive contents, scientific file hashes, inherited transport and frozen runtime before any provider call. `launch.sh` invokes the explicit one-shot deployment; it never continues a previous checkpoint.

The remote owner verifies the guard and executes prepare, disposable profile, measured pin and production. A persisted production checkpoint at update 3 must verify fresh constructor equality, full named Adam state, stream/scheduler/RNG and changed parameter groups. The launcher downloads those bytes and reloads them on CPU before reporting active training. Positive finite profile/production timing ratios are recorded; a slowdown warning does not stop healthy optimizer progress. The unchanged deadline and worker reserve still bound the run, and any reduced actual exposure must be reported.

The pod PID1 guard publishes bounded scientific status to a private, never-deployed provider record. Deadline or failure calls stop before status networking. Complete finalization requires all artifact digests, final per-condition/event coverage and both execution owners gone. A healthy reserve stop with complete final tests may finalize with actual updates below the unchanged pinned exposure only when explicitly labelled `wall_budget_reserve`, `cap_limited=true`, and `exposure_completed=false`; signals and errors remain failures. It gives the already-started laptop mirror at most 120 seconds to finish retrieval; the absolute creation deadline always overrides this grace. Receipt upload permits immediate completion stop. The guard keeps retrying stop independently of the laptop and retains storage if retrieval is incomplete.

The detached laptop mirror starts before profile/production, polls every 15 seconds and stores checkpoint plus metadata snapshots. It verifies every completed scientific artifact and CPU reloads both selected and terminal checkpoints before acknowledging retrieval. It deletes only this attempt's ephemeral pod after complete local verification and an exact stopped-pod readback, then checks provider-list absence. Incomplete retrieval never triggers deletion or GPU restart. Prior pods and results remain untouched.

Offline tests cover deadline/failure/finalization, stop priority, bounded retrieval grace, quote/storage limits, no duplicate/parallel rental, source/hash tamper rejection, mirror integrity and exact-pod cleanup. The native handshake test exercises the actual native batch32/micro4 worker with separate fresh profile and production state, then local downloaded-checkpoint verification.
